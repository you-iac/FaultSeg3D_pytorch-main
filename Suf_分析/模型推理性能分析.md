## 测试结论

- 数值上最快的是 `02_Unet_ConnLoss_8`，完整数据遍历耗时 15.113 s，吞吐量 13.23 样本/s；它与 Baseline 的差异远小于单轮测量波动，不应解读为结构加速。
- 普通 U-Net 三组的峰值已分配显存都是 1495.7 MiB，是本次测试中最低值。
- `00` / `02` / `04` 使用同一普通 U-Net 结构；它们的损失函数不同，但损失函数不参与推理，因而耗时和显存应当接近。
- `03` / `05` 使用同一 SurfaceConv U-Net 结构，推理成本差异主要是单轮测量波动，而不是 Surface loss 造成的。

## 综合分析

- 训练历史文件更新：`01_Unet_DCN4X2` 现已补齐50个epoch的 `train_result.xlsx`、`val_result.xlsx` 和对应日志。其训练曲线与损失映射已同步写入《模型训练过程与损失函数分析.md》；本报告中的推理速度、显存和CPU占用测试不依赖训练曲线，因此推理基准结果保持不变。

- **普通 U-Net 组（`00` / `02` / `04`）**：整轮耗时范围为 15.113–15.642 s。`ConnLoss` 和 `SufLoss` 只改变训练目标，不改变前向结构，所以推理参数量、显存和速度与 Baseline 基本一致。
- **DCN**：参数量是 Baseline 的 1.67×，整轮耗时是 1.79×，吞吐量下降 44.2%。峰值已分配显存只增加 0.8%，但 allocator 峰值保留显存增加 38.7%。
- **SurfaceConv**：参数量是 Baseline 的 3.60×，整轮耗时约为 4.44×，吞吐量下降 77.5%。峰值已分配显存仅增加 1.5%，原因是 128³ 全分辨率特征图的激活内存占主导；但保留显存和 CPU 峰值工作集分别比 Baseline 高 37.7% 和 23.8%。
- **SurfaceConv + Loss**：与纯 SurfaceConv 的整轮耗时只相差 0.107 s，证明 Surface loss 不会额外增加部署时的前向成本。
- **选型建议**：如果后续准确率、Dice/IoU 和连通性指标提升不明显，普通 U-Net 组的推理性价比最高；DCN 和 SurfaceConv 需分别用约 1.79× 和 4.44× 的时间代价来换取指标改善，应结合后续精度结果再决定。

## 测试口径

- 数据路径：`data/data_3D_400/train/x`。
- 该路径实际只有 **200** 个 `.npy` 输入，而不是 400 个；`data_3D_400` 是目录名。本次已对当前训练分割中所有现有输入完整推理一轮。
- 输入形状：`[1, 1, 128, 128, 128]`，类型 `float32`，batch size = 1。
- 仅加载训练集 `x` ，不加载标签 `y`；输出用后立即丢弃，不包含结果落盘时间。
- 模型使用 `eval()` + `torch.inference_mode()`，FP32，未使用 AMP，DataLoader `num_workers=0`、`pin_memory=False`、`shuffle=False`。
- 每个模型正式计时前预热 5 个样本；预热不计入正式耗时。
- “整轮耗时”包含 `.npy` 读取、CPU到GPU传输、模型前向和 Python/DataLoader 循环开销；“GPU前向”仅用 CUDA Event 统计 `model(batch)`。
- “已分配显存”是 PyTorch CUDA allocator 实际被张量占用的峰值；“保留显存”是 allocator 从 CUDA 保留的峰值，不等于 `nvidia-smi` 中的整机显存数。
- CPU 内存为 Windows 进程峰值工作集，包含 Python、PyTorch/CUDA 运行库和模型加载开销。
- 每个模型只测一个完整数据遍历；小差异可能来自 GPU Boost、温度、文件系统缓存和后台负载。
